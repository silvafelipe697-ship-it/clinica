Introdução

O crescimento da demanda por atendimentos ambulatoriais exige clínicas médicas estruturadas com processos ágeis, controle confiável de cadastros, regras claras de triagem e fluxos bem definidos entre recepção e corpo clínico. Este trabalho apresenta a concepção e prototipação técnica da Clínica Vida+, integrando metodologias ágeis, programação estruturada em Python, lógica matemática aplicada à triagem, filas de atendimento e modelagem UML.

Objetivos do Projeto

  • Gestão Ágil: Organizar o desenvolvimento em sprints com quadro Kanban interativo e relatórios de retrospectiva.
  • Automação em Python: Desenvolver o sistema executável clinica_vida.py para cadastro e estatísticas de pacientes.
  • Lógica de Triagem: Validar formalmente regras de liberação para consultas normais e emergências via tabelas-verdade.
  • Estrutura de Dados: Implementar algoritmo FIFO para organização da ordem de chamada de pacientes.
  • Modelagem UML: Representar atores, casos de uso e dependências obrigatórias (<<include>>).

PASSO 3

Lógica Proposicional e Tabelas-Verdade de Triagem

A = Tem agendamento
B = Documentos válidos
C = Médico disponível
D = Pagamentos em dia

Modalidade 1: Consulta Normal

Pnormal = (A ∧ B ∧ C) ∨ (B ∧ C ∧ D)

Situações em que o atendimento é liberado: 3 de 16 (18,75%)

Modalidade 2: Emergência

Pemergência = C ∧ (B ∨ D)

Situações em que o atendimento é liberado: 6 de 16 (37,50%)

Simulador Interativo de Triagem (Teste qualquer combinação)

Análise Detalhada do Caso: A = F, B = V, C = V, D = F

Cenário: O paciente comparece sem agendamento prévio (A = F) e com pendência financeira (D = F), porém apresenta documentos válidos (B = V) e há médico disponível (C = V).

  • Consulta Normal: (F ∧ V ∧ V) ∨ (V ∧ V ∧ F) = F ∨ F = F (NEGADO).
    Justificativa: Ambas as cláusulas exigem B e C verdadeiros combinados com A ou D verdadeiro. Como tanto o agendamento quanto os pagamentos são falsos, a consulta normal não é autorizada.
  • Emergência: V ∧ (V ∨ F) = V ∧ V = V (LIBERADO).
    Justificativa: Na emergência, exige-se médico disponível (C = V) e ao menos documentos válidos ou pagamentos em dia (B ∨ D). Como B = V torna a disjunção verdadeira, o atendimento emergencial é liberado imediatamente.

PASSO 4

Algoritmo de Atendimento em Fila FIFO (First-In, First-Out)

algoritmo_fila_fifo.portugol Pseudocódigo Estruturado 
ALGORITMO FilaAtendimentoClinicaVidaPlus
TIPO
    Paciente = REGISTRO
        nome: CARACTERE
        cpf: CARACTERE
    FIM_REGISTRO

VAR
    fila: VETOR[1..10] DE Paciente
    inicio, fim, i: INTEIRO
    p1, p2, p3, atendido: Paciente

INICIO
    // Inicialização da fila vazia
    inicio <- 1
    fim <- 0

    // 1. Inserção de três pacientes (Enqueue)
    p1.nome <- "Mariana Costa";  p1.cpf <- "111.222.333-44"
    fim <- fim + 1
    fila[fim] <- p1

    p2.nome <- "Carlos Mendes";  p2.cpf <- "222.333.444-55"
    fim <- fim + 1
    fila[fim] <- p2

    p3.nome <- "Fernanda Alves"; p3.cpf <- "333.444.555-66"
    fim <- fim + 1
    fila[fim] <- p3

    // 2. Remoção do primeiro paciente para atendimento (Dequeue)
    SE inicio <= fim ENTAO
        atendido <- fila[inicio]
        inicio <- inicio + 1
        ESCREVA("Em atendimento agora: ", atendido.nome, " - CPF: ", atendido.cpf)
    FIM_SE

    // 3. Exibição dos dois pacientes restantes na ordem correta
    ESCREVA("Pacientes aguardando na fila:")
    PARA i DE inicio ATE fim FACA
        ESCREVA(i - inicio + 1, "º - ", fila[i].nome, " (CPF: ", fila[i].cpf, ")")
    FIM_PARA
FIM_ALGORITMO

Explicação Conceitual (FIFO)

A estrutura de dados Fila (Queue) opera sob o princípio FIFO (First-In, First-Out) — o primeiro elemento inserido é obrigatoriamente o primeiro a ser removido. Na recepção da Clínica Vida+, isso garante justiça cronológica: ao inserir Mariana, Carlos e Fernanda, a primeira chamada remove Mariana (ponteiro inicio avança), mantendo Carlos em 1º lugar de espera e Fernanda em 2º lugar.
